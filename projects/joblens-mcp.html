The problem.

An assistant needs current job listings and resume context to give useful search support. That context should not require storing a job-platform password or automating a logged-in browser.

How I approached it.

I expose job search, local resume parsing and skill matching through FastMCP. An isolated Adzuna client supplies job listings while local parsing extracts resume fields. The match score reports matched and missing skills so the result can be inspected.

What I learned.

Separating the job-data adapter from the tool layer keeps a provider change from spreading through the MCP interface. An explainable score is useful for search exploration, but should not be presented as an assessment of someone's ability.
